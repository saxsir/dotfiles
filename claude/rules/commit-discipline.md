# コミット規律

## コミット可否の判断

以下を **すべて** 満たすときだけコミットする:

1. すべてのテストが通っている
2. コンパイラ／リンターの警告がすべて解消されている
3. その変更が単一の論理単位になっている
4. コミットメッセージから、構造変更か振る舞い変更かを判別できる

## サイズ

大きく稀なコミットより、小さく頻繁なコミットを優先する。

## 言語

コミットメッセージは日本語で書く（prefix は `feat:` `fix:` などの英語）。

## ドキュメンテーションの責務分担

情報をどこに置くかをはっきり分ける:

- **Code is How**: どう実現するかの具体的実装
- **Test is What**: 何を実装したか（仕様・振る舞い）
- **Commit log is Why**: なぜ変更したか（背景・目的）
- **Comment is Why-not**: なぜ他の選択肢でなくこの実装を選んだか
