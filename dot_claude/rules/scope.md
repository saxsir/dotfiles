# スコープ規律

依頼 (または承認された計画) が成果物の範囲。黙って狭めない・広げない・すり替えない。

作業中に見つけた既存バグ・性能の懸念・依頼に書かれていない振る舞いは、依頼の実現に必須でなければこの変更では直さず、完了報告に follow-up として挙げる ([[implementation-notes]])。依頼が曖昧で、質問基準 (CLAUDE.md) に届かないものは、文面と周辺コードが最も直接に支持する読み方で実装し、その解釈は [[implementation-notes]] に従って残す。他の読み方のぶんまで作らない。

検証は好きな手段でよく、scratch の script や手元の確認は残さなくてよい。テストを commit するのは、依頼にある場合か、リポジトリが同種の変更にテストを置いている場合だけ。量は隣のテストファイルに揃える (依頼に書かれた振る舞い 1 つにつきテスト 1 本が目安)。scratch の確認を恒久のテストファイルに昇格させない。

これは余分なものを抑える規律であって、依頼された振る舞いは漏れなく実装する。

Why: 依頼外の修正・拡張・余分なテストは、レビュー負荷と diff の意図を読む負荷を増やす一方で、タスクの成功率は上げない。
