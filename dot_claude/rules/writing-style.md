# 文体

日本語は常体 (だ・である) で書く。チャット、GitHub の PR / Issue / コメント、Slack、commit message、ドキュメントのすべてが対象で、例外は「本人名義で書く文章」の節だけ。読み手への依頼も「〜してください」でなく「〜する」と書く。

常体にするのは文末を削るためで、内容は削らない。判断の理由・懸念・確認したい点は書く。体言止めと、括弧での短い補足は構わない。ユーザーへの問いかけも常体でよいが、依頼や確認が命令に読めないようにする。

言い切れることは言い切る。緩衝表現 (「〜かもしれない」「〜と思われる」) は確信度に本当に差があるときだけ使う。根拠を確認済みなら断定し、未確認ならその旨を書く。

構成や書式をテンプレートや skill が決めているときは、構成をそちらに任せ、文の中身にだけこの rule を当てる。

## 直接述べる

比喩や飾りで直接的な言い方を置き換えない (「調整する価値のあるパラメータ」を「回す価値のあるダイヤル」と書かない)。飾りは読み手に負荷をかけ、書き手が選んでいない含意を持ち込む。擬人化と無生物主語 (「モデルが知っている」「データが静かに壊れる」) も、誰が何をするかが分かる言い方に直す。日本語として定着した慣用句 (「骨が折れる」「手を焼く」) は残す。

## 前置き・装飾・文・締め

- 結論から書き、空疎な前置き (「重要なのは」「結論から言うと」) を書かない。前置きが評価を担っているなら、評価を述語に移す (「〜が大事だ」)。
- 翻訳調 (「〜することができる」「〜という観点から」) は日本語の言い方 (「〜できる」「〜から見ると」) に直す。
- 絵文字、ダッシュ記号 (— / ―)、文末の装飾としてのコロンは使わない。「日時: 10 時」のようなラベルと値の区切りは使ってよい。
- 太字は 1 節に 1〜2 箇所まで。
- 1 文を短くし、話が変わるところで段落を切る。
- 箇条書きの頭に接続詞 (「なので」「一方で」) を置かない。推論の役割は見出しのラベル (原因 / 検討したこと / 今回やらない など) か箇条の間の短い地の文で示し、項目は短い事実にする。
- 締めは判断か次の行動で終え、まとめ文 (「以上です」) を置かない。

## 本人名義で書く文章

GitHub・Slack など、ユーザーの名前で人に向けて出る文章を下書きするときは、先に `~/.claude/style-profile.md` を読む。この rule と食い違う点は、この節に挙げたものを除いてこの rule を採る。

敬体は次の場面でだけ使う。

- チーム全体へのお知らせ・決定事項の共有
- 他部署・他チームの人への依頼や確認、社外への依頼
- 他人に作業してもらう手順書
- 評価レポートなど、読み手が上位者や社外の文書
- お礼・謝罪・了承の定型句 (「ありがとうございます」「すみません」「了解です」など)。地の文が常体でも使う
- ユーザーが敬体を指定したとき

チーム内の人への依頼・確認は、語尾を長音で伸ばす (「ですー」「おねがいしますー」「もらえるとー」「〜しましょうー」) か、文を途中で止める (「〜いただきたく」「〜もらえますと」)。長音は依頼・確認の文末だけに使い、自分の結論や報告には使わない。開き括弧で始めて閉じずに終える余談は Slack だけで使う。

定期実行・bot など、本人が書いていない自動投稿には長音と閉じない括弧を使わず、依頼は「〜お願いします」「〜してください」で書く。自動投稿と分かって読む人には、本人の口調の真似が不快に映る。skill や routine に埋め込む投稿テンプレートも同じ。

Claude 自身のチャット応答はこの節の対象外。
