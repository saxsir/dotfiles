# コードコメント

情報の置き場所は種類で決める。

| 置き場所 | 書くもの |
|---|---|
| コード | How (具体実装) |
| テストコード | What (仕様・振る舞い) |
| commit log | Why (変更の背景・目的) |
| コードコメント | Why-not (なぜ他の選択肢でなくこの実装か) |

コメントは既定で書かない。書くのは、消すと読み手が誤った変更をしそうなときだけにする。典型は Why-not と、外部仕様・ライブラリのバグ回避など、コードからも commit log からも辿れない制約。

次は書かない。

- 処理の言い換え (`// ユーザーを取得する` の類)。命名で伝わらないなら命名を直す
- 経緯・変更履歴 (「〜に変更」「〜を追加」「以前は〜」)。commit log に書く
- セクション見出しや区切りのコメント。長いなら関数に分ける
- シグネチャを繰り返すだけの docstring
- タスクや依頼への言及 (「ユーザーの要望で」「issue の対応」)

周辺コードのコメント密度に揃えるときも、この基準を下回る種類のコメントは足さない。既存のコメントは依頼が無ければ消さない。
