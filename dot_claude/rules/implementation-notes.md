# Implementation Notes

実装中に自分で決めざるを得なかった選択、依頼から逸脱・解釈した点、確認してほしい事項は書き残す。該当がなければ省略してよい。

その commit に閉じる判断 (採った設計と、それを選んだ理由) は commit message の本文へ。PR 横断の判断 (依頼から意図的に外れた箇所とその理由、再検討してほしい事項) は PR description に節を足して書く ([[github-workflow]])。コード読解上どうしても必要な Why-not はコード内コメントに置く ([[commit-discipline]] の責務分担に従う)。

チャットの完了報告でも該当する判断を短く挙げる。ユーザーが目を通すためのものなので commit / PR と重複してよい。
