# Implementation Notes (実装記録)

明確な実装タスク（SPEC を伴う「実装して」「機能を追加して」「〜を作って」等の指示）を受けたら、
着手前にユーザーへ確認する:

> 今回のタスクで implementation-notes を生成しますか？

「はい」なら、`.claude/notes/<YYYY-MM-DD>-<slug>.html` を作業中リポジトリに作成し、
実装が進むたびに追記する。

## 発火条件

- SPEC を伴う実装指示を受けたときに発火する
- 質問・調査・1〜2 行の小修正・既存挙動の説明では発火しない（ノイズ回避）
- ユーザーが「ノート不要」と明示したタスクでは確認を省略する

## ノートに書くこと

「SPEC からどう逸脱・解釈したか」を、ユーザーが後で読み返せる形で逐次追記する。
該当が無い項目は省略してよい:

- **Design decisions**: SPEC が曖昧で、自分で決めざるを得なかった選択
- **Deviations**: SPEC から意図的に外れた箇所と、その理由
- **Tradeoffs**: 検討した代替案と、採用した案を選んだ理由
- **Open questions**: ユーザーに確認 / 再検討してほしい事項

## ファイル仕様

- 配置: `.claude/notes/<YYYY-MM-DD>-<slug>.html`（作業中リポジトリのルートから）
- 形式: HTML。ブラウザでそのまま開ける素朴な構造でよい（CSS / JS 不要）
- `<slug>` は SPEC を表す kebab-case の短い英語名（例: `add-docker-aliases`）
- 1 タスク = 1 ファイル。同タスク内の進捗は同ファイルに追記する
- `.claude/notes/` をコミットするかは各リポジトリの方針に従う

## 完了時

タスク完了報告の最後にノートファイルのパスを 1 行添える。
要点はチャットの最終応答にも残し、ユーザーがノートを開かなくても把握できるようにする。
