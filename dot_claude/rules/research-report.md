# 調査レポート

複数の資料を読んで分析レポートを作る依頼 (競合調査、技術比較、監査、論点整理) に適用する。単一の問いに一次情報で答えて Markdown を残すだけなら `research` skill の領分で、この規則は使わない。コード変更の依頼にも適用しない。

## 進め方

1. 2〜3 資料だけ自分で読んで方針を立てる。観点の候補と、資料としての型 (章立て、比較軸、使う図の種類) を決める。
2. 型を 1 本作った段階でユーザーにレビューを依頼する。全量に進む前に観点の補足と出力方針のフィードバックを受ける場なので、ここを飛ばして全量を仕上げない。
3. 型が固まったら残りの読み込みと観点抽出を `model: sonnet` の subagent に並列で降ろし ([[delegation]])、自分は統合と分析に回る。

## 成果物の形

- ホワイトペーパー形式。HTML をベースにし、Artifact tool があればそれで公開する。
- わかりやすさより詳細さ。要約で内容を削らず解析的に書き、根拠 (資料の該当箇所、一次情報の URL) を付ける。削らないのは内容であって、文は [[writing-style]] どおり短くする。
- 構造・関連・差分は図にする (mermaid か inline SVG)。文章の列挙で済ませない。
