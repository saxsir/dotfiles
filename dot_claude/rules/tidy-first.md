# Tidy First

構造変更 (リネーム / 抽出 / 移動など、振る舞いを変えないもの) と振る舞い変更を分ける。同じコミットに混ぜず、両方必要なら構造変更を先に置く。どちらの変更なのかは commit message から判別できるようにする。

テストがあるリポジトリなら、構造変更の前後で走らせて振る舞いが変わっていないことを確かめる。

既存コードの refactor が要ると判断したら、先に refactor だけの PR を作り、feature はその上に積む。dude の `simplify-code` が整えるのはその PR が足した diff だけなので、既存コードの構造変更は別 PR にしないと誰も拾わない。feature branch に構造変更のコミットが混ざったら、cherry-pick で refactor PR に切り出す。分離できないほど絡んでいるときだけ同じ PR に残す。
