# GitHub に書く文章

読み手は人間。情報の網羅性より読者の認知負荷を優先する。AI 実行向け issue にも適用 (AI は人間向け文章を読めるが逆は不可)。

## 2 層構造

本文には人間向けの文章だけ。行番号付きコード根拠・網羅チェック表・仕様準拠表・生データは末尾の `<details>` に集約 (内部の密度は無制限、AI 再調査用)。

## 本文の規則

- 冒頭に「結局どうなのか」を 3 文以内で。見出し・表より結論を先に。
- 完結した文で書く。体言止め・ダッシュ・括弧補足の断片を並べない。
- 表は短い列挙事実のみ。セル内に複文・根拠・コード参照を入れない。
- 状態記号 (✅⚠️❌) は本文で使わない。太字は段落あたり 1 箇所程度。
- 行番号付きコード参照は details へ。本文では言葉で指す。

## コメント投稿

3 行以上、または手順 / ログ / コード片 / 表を含むなら `<details><summary>1 行要約</summary>本文</details>` で畳む (summary 直後に空行)。短い相槌はそのまま。
