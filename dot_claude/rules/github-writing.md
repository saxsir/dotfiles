# GitHub に書く文章

GitHub issue / PR の本文・コメントの文章規約。手順・操作は GitHub ワークフローを参照。
読み手は人間とし、情報の網羅性より読者の認知負荷を優先する。AI に実行させる issue にも例外なく適用する（AI は人間向けの文章を読めるが、逆は成り立たない）。

## 2 層構造: 人間向け本文 + AI 向け details

本文には人間向けの文章だけを書く。行番号付きのコード根拠・網羅チェック表・仕様準拠表・生データなどの高密度情報は、本文に混ぜず末尾の `<details>` に集約する。details 内の密度は無制限で、AI が再調査・再実行するための情報はここに残す。

## 本文の規則

- 冒頭に「結局どうなのか」を 3 文以内の段落で書く。見出し・表より先に結論。
- 完結した文で書く。体言止め・ダッシュ・括弧補足で圧縮した断片を並べない。
- 表は短い列挙事実のみに使う。セル内に複文・根拠・コード参照を書かない。説明が必要なら前後の文章に出す。
- ✅⚠️❌ 等の状態記号は本文で使わない。太字は段落あたり 1 箇所程度に抑える。
- 行番号付きのコード参照（`crawler.go:80` 等）は details へ。本文では「クローラの取得処理」のような言葉で指す。

## コメント投稿の整形

本文が 3 行以上、または手順 / ログ / コード片 / 表を含む場合は `<details><summary>1 行の要約</summary>本文</details>` で畳む。`<summary>` 直後に空行が必要。短い相槌はそのまま投稿。
