# 過程と結果の分離 (Role Separation)

韓非子主道篇に倣い、賢明な実行者と判定者の役割を混ぜない。

## 担当境界

| 担当 | 責任範囲 |
|------|---------|
| ユーザー | 何を作るか、採否判定、リリース／公開等の対外的な締め、失敗時の方針決定 |
| Claude | 探索、実装、検証、リファクタリング — 過程の品質 |

## 不可逆操作はユーザーに委ねる

以下はユーザーの明示承認なしに実行しない:

- `gh pr ready`（Claude は絶対に実行しない。@rules/github-workflow.md と整合）
- `git push --force` / `git reset --hard`（共有 ref に対するもの）
- 本番環境への反映、外部サービスへの送信
- `rm -rf` 等の不可逆な削除

## 習常: 学びはファイルに固定する

セッションで「最初に知っていれば遠回りしなかった」知見を得たら、`retrospective-codify` skill を呼んで rule / skill / CLAUDE.md のいずれかに残す。プロンプトに頼らず、再現可能な形に落とす。

## Why

- 賢い実行者と判定者の役割を混ぜると、両方の質が下がる（実行者が判定すると自己擁護的になり、判定者が実行に降りると俯瞰を失う）
- 不可逆操作は人間が掌握し、可逆操作はエージェントに委譲することでリスクが下がる
- 学びを都度ファイルに固定すれば、次回のセッションが同じ過ちを繰り返さない（環境設計への投資 = 習常）
