description: Creates a git commit with a Japanese message by analyzing staged and unstaged changes. Use when the user wants to commit current changes or mentions committing code.

## Context

- Current git status: !`git status`
- Current git diff (staged and unstaged changes): !`git diff HEAD`
- Current branch: !`git branch --show-current`
- Recent commits: !`git log --oneline -10`

## あなたのタスク

意味のある日本語メッセージで単一のgitコミットを作成してください。

## コミットワークフロー

**進捗チェックリスト:**
- [ ] ステップ1: 変更内容を分析・分類
- [ ] ステップ2: コミットタイプを決定
- [ ] ステップ3: コミットメッセージを下書き
- [ ] ステップ4: コミット前に検証
- [ ] ステップ5: ステージングとコミット
- [ ] ステップ6: コミット後の検証

---

**ステップ1: 変更内容を分析・分類**

コンテキストに表示された変更をすべて確認し、以下を判定する:

1. **変更の分類**: 各変更が以下のどちらに該当するか判定
   - **構造変更（structural）**: リネーム、メソッド抽出、コード移動など動作を変えない変更
   - **動作変更（behavioral）**: 新機能追加、バグ修正など実際の動作を変える変更

2. **変更の範囲**: どのモジュール/コンポーネントが影響を受けるか

3. **単一論理単位の確認**: 変更が単一の論理単位か確認

> **複数の論理変更が混在する場合**: ユーザーに「この変更には複数の論理単位が含まれています。コミットを分割しますか？」と確認し、指示を待つ。構造変更と動作変更が混在する場合も同様に警告する。

**ステップ2: コミットタイプを決定**

Conventional Commits形式を使用:
- `feat`: 新機能または機能追加（behavioral）
- `fix`: バグ修正（behavioral）
- `refactor`: 動作を変更しない構造変更（structural）
- `docs`: ドキュメント変更
- `test`: テスト追加または修正
- `chore`: ビルドプロセス、依存関係更新など
- `style`: コードフォーマット（structural）

**ステップ3: コミットメッセージを下書き**

形式（日本語）:
```
<type>: <日本語の件名>

<なぜ必要だったかの説明（日本語）>
```

**メッセージガイドライン:**
- **件名**: 何を変更したかの簡潔な要約（50文字以内）
- **本文**: なぜこの変更が必要だったかを説明（どのように実装したかではない）
- 動機と文脈に焦点を当てる
- 該当する場合はissue番号を参照
- リポジトリの最近のコミットのスタイルに合わせる

**例（動作変更）:**

```
feat: ユーザー認証にJWTトークンを実装

セッション管理のスケーラビリティ向上のため、
ステートレスな認証方式に移行した。
```

```
fix: レポート画面の日付表示エラーを修正

タイムゾーン変換時にUTCタイムスタンプを
一貫して使用するように修正した。
```

**例（構造変更）:**

```
refactor: エラーハンドリングロジックを抽出

次の機能追加を容易にするため、
共通のエラー処理を別メソッドに分離した。
```

```
style: importの並び順を標準規則に統一

可読性向上のため、グループごとに整理した。
動作に変更はない。
```

**ステップ4: コミット前に検証**

以下を確認:
- [ ] 変更にシークレットや認証情報が含まれていない（`.env`、APIキー、パスワード）
- [ ] 変更がコミットメッセージの説明と一致している
- [ ] 関連する変更のみが含まれている（単一の論理単位）
- [ ] 構造変更と動作変更が混在していない

> **検証失敗時の対処:**
> - **シークレット検出** → 該当ファイルを `git add` から除外し、ユーザーに報告
> - **複数論理変更の混在** → ユーザーにコミット分割を提案し、指示を待つ
> - **メッセージと変更の不一致** → ステップ3に戻り、メッセージを修正

**ステップ5: ステージングとコミット**

単一のレスポンスで実行:
1. `git add` で関連するすべてのファイルをステージング（シークレットを含むファイルは除外）
2. `git commit -m "<message>"` でコミットを作成（日本語メッセージ）
3. 他のテキストを出力したり、他のアクションを実行しない

**ステップ6: コミット後の検証**

`git status` を実行し、コミットが正常に完了したことを確認する。
